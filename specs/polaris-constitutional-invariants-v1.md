# Polaris Constitutional Invariants v1

Status: CANONICAL / ARCHITECTURE-LEVEL

## Objective
Prevent architectural, semantic, operational, and human-interface drift while preserving Reality's right to overturn any prior model.

These are gradients and burden-of-proof defaults, not dogma. A change may violate a default only when consequential reality or explicit objective requires it and the displaced burden is accounted for.

## Constitutional gradients
- REALITY > MODEL CONSISTENCY
- EVENTS/DELTAS > REPEATED SNAPSHOTS
- EVIDENCE > CLAIMS; observation != inference != prediction
- MORE CAPABILITY > MORE MACHINERY
- LESS HUMAN ATTENTION > MORE HUMAN-VISIBLE INFORMATION
- SHARED SEMANTICS > DUPLICATION
- INHERIT + STORE DELTA > SHADOW COPY
- DERIVED/REHYDRATABLE STATE > UNNECESSARY PERSISTED STATE
- PASSIVE/STATIC/DETERMINISTIC > ACTIVE/MECHANICAL/SOFTWARE/MODEL when decision-equivalent
- EXISTING STANDARD/COMMODITY INTERFACE > CUSTOM
- REVERSIBLE/REPLACEABLE PAYLOAD > PERMANENT OBLIGATION
- LOCAL/INCREMENTAL CHANGE > GLOBAL RECOMPUTATION
- COMPOSITION/EXISTING PRIMITIVE > NEW SUBSYSTEM
- SILENCE > NON-ACTIONABLE OUTPUT
- SIMPLE ADEQUATE MECHANISM > CLEVER MECHANISM
- WHOLE-SYSTEM COST > LOCAL METRIC WIN
- ACCESS/SERVICE/RECOVERY > CONCEALED FRAGILITY
- HUMAN SOVEREIGNTY/AUTHORITY BOUNDARY > AUTOMATION CONVENIENCE

## Human-interface invariant
Default human projection is WHAT CHANGED -> DIRECTION -> CONSEQUENCE/ACTION. Stable background collapses. Detail expands only when it can change understanding, confidence, choice or action, or when explicitly requested. Internal fidelity is never reduced merely to make the projection short.

## Optimization order
DELETE -> SIMPLIFY -> STANDARDIZE -> SHARE/INHERIT -> REUSE -> PASSIVE -> AUTOMATE NECESSARY WORK -> OPTIMIZE SURVIVORS.
Machine optimization follows semantic/work elimination.

## No-new-noun gate
A proposed new named subsystem/domain/engine/registry first attempts representation as an instance, semantic delta, relation, operator, projection, adapter, composition, or existing primitive. A new noun requires an unresolved requirement and demonstrated inadequacy of existing shapes.

## Conservation ledger
Every consequential change accounts for material deltas to:
ATTENTION; COMPLEXITY; PERSISTED STATE; DEPENDENCIES; PERMANENT OBLIGATIONS; RESOURCE/CAPITAL BURDEN; AUTHORITY; FAILURE SURFACE; RECOVERY BURDEN; MAINTENANCE; REVERSIBILITY; OPTIONALITY.

Capability gain alone is insufficient justification. Accounting may be qualitative when precision would not change the decision.

## Optimization receipt
Consequential optimizations record:
- objective/protected constraint;
- burden removed;
- mechanism deleted/simplified/replaced;
- resulting invariant/default;
- assumptions/boundaries;
- evidence/verification;
- reversal trigger: what changed reality would justify undoing it.

Receipts preserve why an optimization exists so future work cannot silently reintroduce the removed burden.

## Ratchet with Reality escape hatch
Verified simplifications become defaults. A future change that reintroduces removed attention, complexity, state, dependency, custom machinery, permanent obligation, or human administration carries burden of proof. This is not irreversible: changed reality, requirements, safety, law, authority, or evidence may justify reversal.

## Regression-by-principle gate
Every consequential architecture change asks:
1. Did human-visible output/attention increase? Why?
2. Did persistent state increase? Why can't it derive/rehydrate?
3. Did dependencies or permanent obligations increase?
4. Did a new subsystem/noun appear? Why can't existing primitives compose it?
5. Did semantics/data/logic duplicate?
6. Did authority expand?
7. Did failure/recovery burden increase?
8. Did reversibility/optionality decline?
9. Can old machinery now be deleted?
10. Did a local optimization migrate burden elsewhere?
11. Does it preserve pithy delta-first human interaction?
12. Does Reality still have a clean path to invalidate/recompile the decision?

A YES to burden-increasing questions is not automatic rejection; it requires explicit justification proportional to consequence and irreversibility.

## Drift sentinels
Flag trends toward dashboard/database proliferation, mega-ontology, mega-graph, bespoke schemas, custom standards, mechanism promotion, feature accumulation, state accumulation, notification growth, repeated context, centralization/duplication religion, automation authority creep, speculative future-proofing, optimization without stop condition, and architecture-for-the-diagram.

## Self-pruning
When new capability makes old machinery redundant, deletion is part of completion. A feature is not fully integrated while superseded parallel doctrine/logic remains authoritative without reason.

## Stop condition
Stop optimizing when additional work no longer materially improves objective attainment, confidence, total lifecycle burden, optionality, or action. Analytical and architectural complexity must earn its keep.

## Polar / failure modes
Constitution worship; frozen architecture; metricized bureaucracy; optimization-receipt spam; deletion fetish; silence hiding material uncertainty; passive-mechanism dogma; standards dogma; local simplicity causing global complexity; under-modeling consequential reality; treating all complexity as bad; refusing justified specialization; refusing new primitives after requirements genuinely change.

Final law: ANCHOR THE DIRECTION, NOT THE IMPLEMENTATION. Preserve the invariants that produced the optimization; permit mechanisms to change when Reality changes.
