# Cross-Domain Survivor Operators v1

Status: canonical semantic contract for `0.1.0-alpha.21`.

These are admitted from the corpus-wide missing-delta reconciliation. They are operators, policies, metrics, projections, or verification gates under existing owners; they MUST NOT create parallel sovereign Fabrics.

## Temporal / evidence

- **Regime-aware rebaseline** — distinguish transient excursion, trend, and persistent regime change before redefining baseline.
- **Adaptive fidelity** — stable regimes may use compressed/low-rate projections; anomalies and transitions increase fidelity. Evidence required for reconstruction/provenance is retained.
- **Memory consolidation** — low-attention/off-peak processing may deduplicate, summarize, generalize, and precompute from retained evidence without rewriting source truth.
- **Forgetting as maintenance** — stale projections may lose retrieval priority; evidence is not deleted merely because it is old.
- **Evidence service hatch** — every consequential projection MUST expose a path to evidence, transforms, assumptions, uncertainty, and decision logic.

## Resilience / control

- **Failure drain** — consequential flows require a bounded safe sink, quarantine, rollback, or equivalent terminal failure path where the domain permits one.
- **Zoned control** — local zones may retain independent bounded control on a shared backbone; central coordination MUST NOT become an unnecessary single point of failure.
- **Slow signal / fast reflex** — slow global policy, budgets, seasons, and strategy are distinct from time-critical local actions. Fast reflexes require bounded prior authority and safe limits.
- **Reproduction proof** — backup existence is not durability. A capability is reproductively proven only when a successor can be reconstructed and verified from retained contracts/state/evidence.
- **Germline / phenotype separation** — preserve the minimum inheritable specification needed to recreate capability separately from replaceable runtime instances and deployments.

## Capability / resources

- **Latent capability reserve** — reachable unused capacity (ports, conduit, space, power, compute, inventory, human slack, etc.) is represented as option value when material, not automatically as waste.
- **Upgrade view** — projections may show reachable future capability enabled by current interfaces, slack, or prerequisites, not only deficits.
- **Inventory capital/option projection** — carrying cost, readiness contribution, lead time, recoverable value, and option value remain separate dimensions.
- **Counterfactual maintenance** — repair/replace/wait decisions compare downtime, repair probability, replacement lead time, mission consequence, lifecycle burden, and option value.
- **Capability commonality** — measure useful configurations/capabilities per unique primitive or interface where this discriminates recombinability; do not maximize variants for their own sake.
- **Ratio-native design** — use relationships/ratios rather than fixed absolute dimensions when scale is incidental to the requirement.
- **Tail-cutter capital** — reusable capital that removes recurring human friction is evaluated by burden removed versus lifecycle burden introduced.
- **Offline capability primitive library** — passive/simple/offline capabilities are discoverable by function and requirement, with local yield, dependencies, interfaces, balances, losses, and failure propagation.
- **Time-envelope completion threshold** — task-value models may represent discontinuous completion-probability gains when total burden crosses an available-time/effort envelope.
- **Technology intrusion constraint** — telemetry/control dependence, software dependency, repair lock-in, provider dependence, and similar technology burdens remain explicit lifecycle/optionality constraints.

## Execution / verification

- **Transition ritual compiler** — recurring transitions may compile to prepare -> execute -> recover -> reset state machines when this reduces burden or failure.
- **Low-cost compute scheduling** — nonurgent consolidation/simulation may be scheduled in low-attention/low-cost windows subject to freshness and deadline constraints.
- **Algorithm red-team contract** — consequential algorithms support counterexample-first validation, independent-enough oracles, property/metamorphic tests, adversarial boundary inputs, and worst-case resource checks as applicable.
- **Constraint-native economic routing** — routing accepts sparse constraints and preserves materially distinct cost dimensions (time, distance, fuel/energy, fees, stops, wear, delay risk, etc.) over replaceable geospatial providers.

## Projection / integration gaps

- **Owned-item external watch binding** — canonical owned-item identity may bind to relevant recalls, service bulletins, compatibility changes, and external deltas through relevance/evidence gates.
- **Finance -> Bearings routing** — financial deltas project into Bearings/Wayfinder without creating a second financial truth store.

## Admission laws

1. `new name != new owner`.
2. Existing standards/interfaces are searched before custom mechanisms are admitted.
3. Native state representations remain authoritative; SBDTT is used only as an evaluated projection where appropriate.
4. Stock, flow, rate, cumulative investment, lifecycle burden, option value, and current state remain distinct quantities.
5. Implementations/providers remain replaceable unless Reality makes that impossible.
6. Any operator that cannot change understanding, choice, verification, or action at adequate resolution should collapse into existing machinery rather than persist as ceremony.
