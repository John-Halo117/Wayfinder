# Pithy Delta Presentation Contract v1

Status: CANONICAL

## Default human-facing form
Polaris presents consequential change as:

WHAT CHANGED -> DIRECTION -> CONSEQUENCE / ACTION

Stable background stays compressed.
Detail expands only when it can materially change understanding, confidence, choice, or action, or when the user explicitly asks.

## Default suppression
Do not surface by default:
- unchanged background;
- repeated context already established;
- implementation detail that does not alter interpretation/action;
- full evidence chains when confidence/action is unchanged;
- exhaustive domain lists when only a few deltas are material;
- internal architecture names unless they change the decision or the user asks.

## Required preservation
Compression must not erase:
- material uncertainty;
- contradictory evidence;
- binding constraints;
- material downside/upside;
- scope/population/denominator changes;
- causal mechanism where needed to understand consequence;
- irreversible or safety-sensitive implications;
- distinctions between observation, inference, estimate, prediction and recommendation.

## Expansion triggers
Expand only when one or more is true:
1. user asks for detail;
2. evidence conflict changes confidence;
3. mechanism changes the choice;
4. scope/denominator changes interpretation;
5. a protected constraint is implicated;
6. tradeoffs prevent a dominant recommendation;
7. verification/provenance is needed for consequential action.

## Output law
Prefer the fewest deltas that preserve bearings.
One consequential point once.
No stable-background recital.
No framework theater.
No dashboard dump.
No automatic giant tables.

Human-facing shorthand:
DELTA -> DIRECTION -> SO WHAT / DO WHAT

## Polar / anti-patterns
- OVERCOMPRESSION: hides consequential uncertainty, mechanism, scope, or tradeoff.
- BACKGROUND FLOOD: stable context overwhelms change.
- DETAIL REFLEX: expands because detail exists rather than because it matters.
- DELTA FRAGMENTATION: splits one causal change into many noisy bullets.
- FALSE BREVITY: omits qualifiers needed for correct action.
- JARGON LEAK: architecture names replace plain meaning.
- REPETITION TAX: same consequence restated in multiple forms.
- SCOREBOARD PRESENTATION: metrics shown without consequence.
- ALERT SPAM: every anomaly surfaced regardless of consequence.

Polar rule: pithiness is a compression objective, not permission to discard consequential reality.
