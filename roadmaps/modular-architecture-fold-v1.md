# Modular Architecture Principles — Fold into Existing Roadmap DAGs v1

Status: CANONICAL DELTA FOLD. This is not a new subsystem or standalone roadmap. These nodes belong to the existing shaped DAG portfolio.

## DAG A — Constitutional / Architecture Kernel
Add/strengthen:
- SEAMS-FIRST: standardize stable seams/interfaces more aggressively than payloads/components.
- TYPE != CANDIDATE != INSTALLED INSTANCE: standards/type semantics, candidate products, and deployed instances remain distinct.
- CAMPUS != BUILDING != PAYLOAD ownership: adjacency does not imply semantic ownership.
- PERMANENT != REPLACEABLE: long-lived substrate may not inherit unnecessary assumptions from short-lived equipment/finishes.
- MODULARITY ADMISSION: modularity must reduce replacement/reconfiguration/service burden more than interface count/complexity adds.
- NEED BEFORE PROCUREMENT: reserve cheap pathways/interfaces early; buy/populate replaceable payloads only when actual demand earns them.
- CAPACITY BY QUANTITY BEFORE BESPOKE: scale repeated qualified modules/bays/components before inventing unique variants when decision-equivalent.
- NO DOUBLE-OWNERSHIP: one consequential fact/requirement has one canonical owner; other locations reference/project it.

Polar failures: LEGO-house syndrome; module proliferation; premature dimensional freeze; payload dictates skeleton; universal-interface delusion; proprietary-house lock-in; custom-standard reflex; interface-without-payload; false compatibility; geometry worship.

## DAG C — Semantic Shapes / Standards / Data Substrate
Add semantic inheritance:
CAMPUS_SUBSTRATE -> BUILDING_INSTANCE -> ZONE/ASSEMBLY -> INTERFACE -> PAYLOAD_INSTANCE.

Shared type-level semantics own repeatable definitions such as window/door/interface classes, plumbing/electrical/service conventions, labels, inspection/maintenance semantics, and dimensional families. GH and MH inherit only shared semantics and retain building-specific deltas.

Canonical identity separation:
STANDARD/TYPE -> QUALIFIED CANDIDATE -> PURCHASED ITEM -> INSTALLED INSTANCE -> CURRENT STATE.

A product SKU or vendor implementation never becomes the standard/type owner.

## DAG H — Physical Polaris Deployment
Add deployment topology:
- CAMPUS_CORE owns shared trunks/routes/demarcations where centralization wins.
- GH/MH/workshop/garage/greenhouse/etc. own downstream local branches/endpoints.
- Every shared backbone terminates at explicit demarcations/isolation points.
- Reserve-during-design targets geometry/routes/clearances/blocking/penetration zones/access; equipment remains ON_DEMAND unless move-in critical.
- External service interfaces may include water/power/data/maintenance ports only when standards, weathering, security, serviceability and failure isolation are satisfied.
- Centralization is not presumed: local life safety, manual shutoffs, access and essential fallback remain local where consequence requires.

## DAG I — Sanctuary / Land / GH / Construction / MH
### Campus substrate
LAND/TOPOGRAPHY/HYDROLOGY/ACCESS -> CAMPUS ROUTES/TRUNKS -> NAMED BUILDING DEMARCATIONS -> LOCAL BUILDING BRANCHES.
The campus substrate is designed before individual buildings where later retrofit would be expensive, but only cheap/high-option-value reserve is installed early.

### GH
GH is a complete compact building instance, not a disposable prototype and not a miniature MH.
- ~1,000 ft2 ceiling/baseline; test 925–975 ft2 only when real envelope can shrink without friction/accessibility loss.
- simple one-story box/gable/repeated spans and openings where reality permits.
- concentrated Wet/Service Core, pantry wall, right-sized laundry, productive boundaries, passive shortcuts.
- minimal/no dedicated hallway by default.
- commodity dimensions/repeated details/advanced framing or manufactured/panelized methods remain challengers, never requirements.
- mini-split/ductless simplicity preferred where actual load/layout supports it; no duct network merely by convention.

### MH
MH is a separate successor building instance with different protected requirements.
- ~2,700 ft2, one story, 4 real bedrooms, 2 baths.
- halls/circulation where they improve privacy/access/legibility.
- richer comfort/hospitality/storage/library/craft/grooming/AV capability may earn additional space and finish cost.
- MH is the deliberate splurge tier: preserve construction/value discipline, but do not force GH austerity where it harms the desired lived state.

### Structure / enclosure / finish separation
LONG-LIFE SKELETON -> CONTROL LAYERS/ENCLOSURE -> SERVICE LAYER -> REPLACEABLE INFILL/PAYLOAD -> REPLACEABLE FINISH/VENEER.
Exterior appearance layers such as stone/brick-look or other veneers are treated as finish/rainscreen payloads where technically compatible; they do not silently become structure or primary water control.
Window tint, stained/decorative glazing and similar aesthetic/solar-control layers are candidates only where light/thermal/maintenance effects justify them.

### Manufacturing/assembly grammar
DESIGN FOR MANUFACTURING + DESIGN FOR ASSEMBLY + DESIGN FOR SERVICE + DESIGN FOR DISASSEMBLY.
Coordinate structure, panels, openings, cabinetry and services around stable commodity dimensions when it reduces unique cuts, scrap, labor and error. Repeat details aggressively. Factory/jig/panel/bay methods compete against site-built baselines on installed lifecycle cost, not novelty.

### Exterior/site low-cost infrastructure
Commodity mass/barrier elements such as concrete masonry units, aggregate, earth, gabion/sandbag-like temporary erosion/flood controls, fencing and landscape berms may serve qualified drainage, erosion, staging, privacy or protective functions. They remain site-specific and must not substitute for engineered retaining/foundation/water-control work when loads/consequences require it.

### External utility/service ports
Group exterior hose/water, electrical/data/maintenance interfaces into hardened, labeled, drained/weather-resistant, isolatable service points where useful. The objective is easier service/use with fewer ad-hoc penetrations, not a gadget-covered exterior.

## DAG L — Products / Ownership / Procurement
Add procurement hierarchy:
REQUIREMENT -> EXISTING CAPABILITY -> STANDARD/COMMODITY INTERFACE -> QUALIFIED PRODUCT FAMILY -> SUPPLIER/PRICE -> PURCHASE -> INSTALLED INSTANCE.

Prefer interchangeable commodity components and multiple-source compatibility. Candidate brands never become architecture. Procurement should exploit repeated parts, batch buying, standard dimensions, off-the-shelf panels/components and shared tooling only when lifecycle economics survive whole-system recompilation.

## DAG N — Preparedness / Resilience / Recovery
Modularity contributes resilience only when failure isolation, replaceability and manual/local fallback improve.
- shared trunks require isolation so a campus fault does not become campus-wide failure.
- replaceable payloads fail independently of durable substrate.
- exterior service ports and utility demarcations require safe isolation/failure states.
- passive site elements may provide useful flood/erosion/temporary barrier capability, but permanent structural protection requires qualified design.
